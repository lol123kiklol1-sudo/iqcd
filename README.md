# بوت نظام إدارة الاشتراكات (Subscriptions Control Bot)

بوت Discord لإدارة اشتراكات بيع البوتات (Games / Music / Tickets / Groups...) بنفس فكرة الصور اللي أرسلتها:
- أمر `/add` لإضافة اشتراك جديد — **مع نظام مخزون (Pool)**: كل نوع بوت عنده عدد محدود من النسخ، والبوت يمنع تكرار توزيع نفس النسخة لشخصين بنفس الوقت.
- عند انتهاء اشتراك، النسخة ترجع "متاحة" تلقائياً لأي زبون جديد.
- زر "اشتراكاتي" بلوحة تحكم رئيسية، يفتح قائمة منسدلة بكل اشتراكات الشخص، ولما يختار وحدة تطلع تفاصيلها مع أزرار التحكم.
- صاحب الاشتراك أو الأدمن يقدر: يوقف مؤقتاً، يستأنف، يسوي ريسيت، ينقل الملكية لشخص ثاني، يغيّر السيرفر.
- فحص تلقائي دوري يحول الاشتراك لـ "منتهي" تلقائياً عند خلاص الأيام (وبنفس اللحظة تصير نسخة البوت متاحة من جديد).

---

## 1. المتطلبات
- Node.js نسخة 18 أو أحدث.
- بوت مسجل في [Discord Developer Portal](https://discord.com/developers/applications).

## 2. خطوات التركيب

```bash
cd subs-bot
npm install
cp .env.example .env
```

بعدين افتح ملف `.env` وعبّي:
- `MAIN_BOT_TOKEN`: توكن البوت الرئيسي (بوت الإدارة).
- `CLIENT_ID`: آيدي التطبيق (Application ID) من الـ Developer Portal — **أضِفه بنفس الملف** حتى لو مو موجود بالمثال.
- `GUILD_ID`: آيدي سيرفر الكنترول (للنشر السريع للأوامر).
- `CONTROL_CHANNEL_ID`: آيدي الروم اللي بيه رومات/كروت الاشتراكات.
- `ADMIN_ROLE_ID`: (اختياري حالياً، الأمر مضبوط على صلاحية Administrator).

وبعدين عبّي ملف `config/bots.json` (راجع قسم "مخزون البوتات" بالأسفل) — هذا **غير `MAIN_BOT_TOKEN`**، هذا لتوكنات بوتات الاشتراكات الفعلية المباعة.

## 3. نشر الأوامر (/add, /panel, /available)

```bash
node deploy-commands.js
```

## 4. تشغيل البوت

```bash
node index.js
```

## آلية الاستخدام

### 1. نشر لوحة التحكم (مرة وحدة)
بروم الكنترول، الأدمن يكتب:
```
/panel
```
هذا ينشر Embed ثابت فيه زر واحد فقط: **"اشتراكاتي 🔶"** (نفس فكرة الصورة اللي أرسلتها).

### 2. مخزون البوتات (config/bots.json)
كل نوع بوت له **عدد محدود من النسخ الفعلية**، كل نسخة عندها توكن وClient ID خاص فيها. مثال بالملف:
```json
{
  "bots": [
    { "type": "GAME", "instanceId": "GAME-4711", "label": "Games#4711", "token": "...", "clientId": "..." },
    { "type": "GAME", "instanceId": "GAME-9012", "label": "Games#9012", "token": "...", "clientId": "..." }
  ]
}
```
- ممكن تضيف كم نسخة تبيها لنفس النوع (`GAME` مثلاً) — كل نسخة لازم `instanceId` فريد.
- لما تنفذ `/add` بنوع معين، البوت يدور تلقائياً على أول نسخة **مو مستخدمة حالياً** (يعني ما لها اشتراك نشط أو موقوف) ويربطها بالاشتراك.
- لو ما فيه ولا نسخة متاحة، البوت يرفض الأمر ويقولك: "⛔ لا يوجد بوتات متاحة حالياً من هذا النوع".
- لما اشتراك شخص ينتهي (تلقائياً بعد خلاص الأيام)، النسخة اللي كانت عنده **ترجع متاحة تلقائياً** لأي زبون جديد.
- استخدم `/available` بأي وقت عشان تشوف كم نسخة متاحة/مشغولة من كل نوع.

### 3. إنشاء اشتراك
الأدمن يكتب:
```
/add الايام:30 ايدي_السيرفر:123456789012345678 الشخص:@user نوع_البوت:Music_10x
```
البوت يحفظ الاشتراك بملف `data/subscriptions.json` (مربوط بنسخة بوت محددة من `config/bots.json`) ويرسل تأكيد + رسالة خاصة (DM) للشخص. **ما ينشر أي كرت بالروم** — الشخص يشوف اشتراكاته فقط عبر زر "اشتراكاتي".

### 4. تجربة المستخدم (Flow)
1. الشخص يضغط زر **اشتراكاتي** بلوحة التحكم.
2. تطلع له رسالة خاصة (Ephemeral) فيها **قائمة منسدلة (Select Menu)** بكل اشتراكاته: نوع البوت + آخر 4 أرقام من المعرف + حالته (لو موقوف/منتهي).
3. يختار اشتراك من القائمة → تطلع تفاصيله الكاملة (Embed) مع أزرار التحكم.

### أزرار التحكم (لصاحب الاشتراك أو الأدمن فقط)
| الزر | الوظيفة |
|---|---|
| 👑 تغيير مالك البوت | يفتح نافذة لإدخال آيدي شخص جديد وينقل له ملكية الاشتراك |
| 🔗 تغيير السيرفر | يفتح نافذة لإدخال آيدي سيرفر جديد |
| ▶️ الحصول على رابط الانفايت | زر رابط مباشر (يظهر فقط إذا كان clientId الخاص بالنسخة المحجوزة مضاف بـ `config/bots.json`) |
| ⏸️ إيقاف مؤقت / ▶️ استئناف | يوقف العد التنازلي مؤقتاً ويحفظ الوقت المتبقي، وعند الاستئناف يكمل من نفس النقطة |
| 🔁 إعادة تشغيل | يسجل طلب "ريسيت" (مكان مناسب لربطه بإعادة تشغيل العملية الفعلية للبوت لاحقاً) |
| 🔍 اكتشاف الاشتراك | يعرض تفاصيل الاشتراك مرة ثانية بشكل خاص |

عند انتهاء الاشتراك تلقائياً، البوت يرسل للشخص رسالة خاصة (DM)، وإذا حددت `LOG_CHANNEL_ID` بالـ `.env` يسجل الحدث هناك أيضاً.

### ملف التوكنات
`config/bots.json` يحتوي كل نسخ البوتات المتاحة للبيع (توكن + Client ID لكل نسخة على حدة).
هذا الملف **غير مرفوع لأي مكان عام** (مضاف بـ `.gitignore`) — عبّيه بتوكناتك الحقيقية بعد التحميل، ولا تشاركه مع أحد.
⚠️ إذا رفعت المشروع باستضافة زي Railway، لازم تحط محتوى هذا الملف كمتغير بيئة أو ترفعه يدوياً بعد النشر — لا ترفعه على GitHub عام أبداً.

## هيكل المشروع
```
subs-bot/
├── index.js                 # نقطة تشغيل البوت
├── deploy-commands.js        # نشر الأوامر
├── commands/
│   ├── add.js                  # أمر /add
│   ├── panel.js                 # أمر /panel
│   └── available.js             # أمر /available (فحص المخزون)
├── handlers/
│   ├── buttons.js             # منطق أزرار التحكم
│   ├── modals.js               # منطق نوافذ تغيير المالك/السيرفر
│   └── panel.js                 # منطق زر "اشتراكاتي" والقائمة المنسدلة
├── utils/
│   ├── storage.js             # قراءة/كتابة قاعدة البيانات (JSON)
│   ├── format.js               # بناء الـ Embed والأزرار
│   ├── botPool.js               # إدارة مخزون نسخ البوتات (متاح/مشغول)
│   └── expiryChecker.js        # فحص انتهاء الاشتراكات دورياً
├── config/
│   └── bots.json                # نسخ البوتات المتاحة للبيع (سري)
├── data/
│   └── subscriptions.json      # قاعدة بيانات الاشتراكات
└── .env                        # إعدادات حساسة (توكن البوت الرئيسي..)
```

## أفكار للتوسعة لاحقاً
- ربط زر "إعادة تشغيل" فعلياً بمدير عمليات مثل PM2 أو Docker لإعادة تشغيل نسخة البوت المرتبطة بالاشتراك.
- ربط فتح التذاكر (Tickets) تلقائياً بإنشاء الاشتراك (بدل ما يكون الأمر يدوي بالكامل من الأدمن).
- الانتقال من JSON إلى قاعدة بيانات حقيقية (SQLite/PostgreSQL) لو عدد الاشتراكات كبير.
- إشعار صاحب الاشتراك بخاص (DM) قبل يوم أو يومين من الانتهاء.
